# Claude 3 — second round: production path and durable plans

Работай в `Mustiks07/headroom`, отдельный clone/worktree, ветка `claude3`. Сначала fetch и обычный merge `origin/main`; без force push/reset. Прочитай AGENTS.md, docs/ARCHITECTURE.md, DEPLOYMENT.md, docs/handoffs/integration-review.md. Main уже содержит общий работающий код и исправления интегратора. Не возвращай foundation engine или старый импортёр.

Твоя зона: APIs, client/server adapters, persistence, Supabase, extraction, PDF/export, package/config/CI. UI-правки для хранения/экспорта минимальные, заранее опиши seam, не переделывай одновременно экраны Claude 1. Shared contract changes согласовать через явный handoff.

## Приоритеты

1. **Сохранённый план после обновления engine.** Сейчас старый fingerprint отклоняется при save/export, но в интерфейсе нет прямого пути обновить план без фиктивного редактирования суммы. Добавь определение устаревшего engine/rules, сохранение прежней версии как истории, явный пересчёт, сравнение и подтверждение нового плана. Не подменяй старое решение молча. Если Claude 2 добавит оценку фиксированных действий, подключи её после согласования функции.
2. **Cloud failure не должен отрезать guest путь.** Конфиг Supabase может существовать, а таблицы/RLS/сеть быть недоступны. После успешной anonymous auth последующий сбой сейчас не означает автоматического local fallback. Дай честный выбор сохранить локально/экспортировать, не потеряв draft и не показывая cloud success. Не смешивай local/cloud ownership и не утверждай, что данные удалены с сервера, если запрос удаления не прошёл. Изоляцию двух гостей проверить на реальном Supabase только после предоставления доступа.
3. **Реальная работа импорта.** Интегратор исправил expense date → amount, неоднозначные CSV columns и частичный разбор сумм. Сохрани это. Улучши удобный импорт pay stub/Marketplace notice/project offer: явные период, год, владелец, факт vs прогноз, пользовательское подтверждение. Доход YTD нельзя без явного решения объявлять полным прогнозом. Никаких авто-предложений классифицировать все банковские поступления как profit. Проверь неверный документ, отказ provider и повторную загрузку без потери формы. Не показывай PDF/image extraction как работающую, пока provider не подключён.
4. **Публичный endpoint с платным AI.** Ограничь request size/pages/timeout и стоимость/частоту обращений так, чтобы ограничения имели смысл на Vercel, а не только внутри одного тёплого процесса. Секреты только на сервере, финансовые payloads не в логах. Не добавляй регистрацию. Опиши какие меры реально действуют без внешнего rate-limit store и какой бюджетный guard нужен при подключении provider.
5. **Восстановление и отчёт.** Проверь JSON restore на schema, версию, fingerprint, неизвестный/infeasible scenario и устаревшие action IDs. PDF уже содержит официальные ссылки и два года: не теряй их. Сделай корректное разбиение длинных строк/таблиц и разумный объём report, без потери данных; проверь длинное название проекта и источник, не только короткий fixture. Реальный PDF экспорт → визуальный осмотр, а не только наличие `%PDF`.
6. **Деплой и handoff.** Подготовь воспроизводимый Vercel/Supabase путь и список действительно необходимых переменных. Сначала весь guest flow без ключей. Если пользователь предоставил доступ, применяй разрешённые настройки и проверяй публичный URL в чистом браузере, anonymous ownership и один реальный consented AI import. Если доступа пока нет, не блокируй остальную работу и не утверждай, что сервис уже подключён. Не включай реальные платежи: конкурсный путь полностью открыт, test/demo checkout явно подписан.

## Готовность

Проверки конечные: локальный round trip; один сценарий ошибки сервиса; stale-plan upgrade; JSON restore; финальный PDF; одна проверка isolation при наличии live DB. Не строить бесконечный тестовый framework. После своих правок — targeted checks и один build; после согласованной интеграции новых веток — конечные user journeys из ACCEPTANCE.md.

Запиши `docs/handoffs/claude3-round2.md`: реальные env/migrations, что проверено локально и на каком URL, что не подключено, что нужно от пользователя. Commit и push в `claude3`; не заменяй main без общей интеграционной проверки. Не отправляй сообщения/письма третьим лицам.
