# Claude 1 — second round: a clear result before a long form

Работай в `Mustiks07/headroom`, отдельный clone/worktree, ветка `claude1`. Сначала `git fetch origin` и обычный merge `origin/main` в свою ветку. Не используй reset/force push. Прочитай AGENTS.md, docs/TZ.md, docs/handoffs/integration-review.md. В main уже соединены работы всех троих: не возвращай старые заглушки или собственную прежнюю копию проекта.

Твои файлы: UI (`src/app` кроме API, `src/components`, `src/features`, `public`), небольшой browser smoke. Движок, сервер, migrations и shared contracts без координации не менять.

## Главная задача

Преврати работающий, но слишком длинный интерфейс в понятный продукт. На открытии семейного demo человек должен быстро увидеть: сколько принесёт заказ как предложен, где возникает потеря субсидии, какие выполнимые варианты есть, и что делать дальше. Сейчас результат находится после большой формы и длинного списка предупреждений. Не требуется менять название, финансовую логику или придумывать новые функции ради количества.

1. **Demo начинается с результата.** Покажи текущую ситуацию, эффект заказа и рекомендуемое действие на первом экране. Рядом — небольшой блок самых важных редактируемых параметров. Полную анкету открывай по явному действию. Числа только из реального engine result; загрузка/needs_data остаются честными. Предупреждения об illustrative/county-candidate данных и условиях рекомендации видны рядом с выводом; длинный аудит можно раскрывать.
2. **Собственные данные вводятся постепенно.** Сначала текущий год и только необходимые вопросы. Предложение клиента и следующий год спрашивай для сравнения. Unknown остаётся unknown. Не подставляй супругу ноль и не подтверждай eligibility за пользователя. Сохраняй draft и корректно восстанавливай его. У каждого сложного вопроса — короткое объяснение, где взять число.
3. **Исправь обработку невалидных денег.** Сейчас MoneyField показывает локальную ошибку, но его `commit` при invalid возвращается без изменения прежнего fact. Это позволяет оставить старое число в расчёте. Невалидное редактирование должно делать результат устаревшим и блокировать расчёт/save/export, пока значение не исправлено; пустое значение и явный ноль различаются. Не своди неправильный ввод к нулю. Проверь также low/high ranges и восстановление draft. Не добавляй числовые вычисления налогов в UI.
4. **Понятное сравнение.** Явно различай «доход от проекта по сравнению с отказом» и «улучшение по сравнению с принятием как есть». Пенсионные деньги не складывать с доступными. Даты и суммы выплат читаются без налогового жаргона. При ограничении SEP показывай причину недоступности, не предлагай неисполняемый план. Не выдавай поиск с указанной погрешностью за математически точный абсолютный максимум.
5. **Просмотр и доступность.** У calculation drawer нужен корректный keyboard focus trap и возврат фокуса. Движок возвращает пути `coverage[*]`: раскрывай соответствующие месяцы и реальные inputs вместо неразрешённого пути. Источники уже подключены через `src/domain/sources.ts`; сохрани ссылки и статус DRAFT. Состояния загрузки, ошибок, отсутствия данных и устаревшего результата должны быть понятны на узком экране.
6. **Короткая проверка реального пути.** Сценарий family → меняем цену и SEP limit → save → reopen → change income должен использовать настоящий engine. Текущий `tests/ui/smoke.cjs` допускает unavailable и требует незаявленный Playwright; сделай проверку воспроизводимой и требующей ready там, где он ожидается. Не создавай большую E2E-систему; одна содержательная проверка плюс осмотр desktop/mobile достаточно.

## Готовность

Все app тексты на английском. Никакой регистрации, email-gate или оплаты для доступа. На 360 px нет горизонтальной прокрутки всей страницы. Реальная сумма меняется после изменения ввода. Состояние ошибки не выглядит успешным. Не скрывай ограничения, но не заставляй человека читать внутреннюю спецификацию до получения результата.

Сделай изменения кодом, проверь затронутый путь и один build. Запиши краткий handoff `docs/handoffs/claude1-round2.md` с изменениями, проверкой, скриншотами при наличии и оставшимися вопросами. Commit и push в `claude1`; не сливай в main самостоятельно. Никаких бесконечных тестов и косметических переписываний всего проекта.
