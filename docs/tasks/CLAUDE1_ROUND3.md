# Claude 1 — household journey and first impression

Ветка `claude1`. Сначала fetch + обычный merge `origin/main`, `npm ci`; прочитай AGENTS, [shared brief](ROUND3_SHARED.md), [integration review](../handoffs/integration-round2.md). Не возвращай старый Workspace и не теряй local fallback/fixed-agreement review. Shared schema приходит первым отдельным коммитом Claude 3; правила денег реализует Claude 2.

## Сделать

1. **Сильный первый экран.** В family demo сейчас высокая третья карточка, длинные инструкции и большая пустота под двумя другими. На 1365×900 основная цифра, смысл двух baseline и CTA должны читаться сразу. В карточках оставить результат и короткое действие, подробные условия раскрывать ниже. На 360px результат не должен теряться после нескольких экранов служебного текста. Сохранить заметную маркировку synthetic и доступность условий; не прятать существенные ограничения. Сделать все пункты мобильной навигации явно доступными, без обрезанного “My plans”.
2. **Прогноз без выдуманного заказа.** В `/check` дать annual total либо YTD net profit + expected remaining receipts − remaining expenses. Простыми словами уточнить период и исключение управляемых проектов. Не требовать прогноз следующего года до межгодового сравнения. Показать состав получившейся суммы и источник; unknown блокирует соответствующий результат.
3. **Один семейный план.** Отображать текущую субсидию, общую ожидаемую прибыль, согласованные проекты и следующее действие. Добавить новый проект B поверх A через API/engine adapters; возврат к списку и повторное открытие работают. Реальные даты/суммы оплат вводятся отдельно от ожиданий, замена проверяется пользователем.
4. **Исполненные действия.** Вместо одного checkbox для SEP — дата, налоговый год и реально внесённая сумма. На экране: годовая цель / уже внесено / осталось. Не показывать всю новую цель как дополнительный платёж. Для старых done-отметок нужна миграционная проверка, не автоматическое “paid”.
5. **Изменение дохода.** Сначала старые фиксированные договорённости при новом прогнозе, затем новые предложения. Дать сохранить обновлённый прогноз, оставив прежние договорённости, даже когда они больше не оптимальны; результат честно показывает риск. Нельзя требовать фиктивное новое соглашение ради сохранения факта.
6. **Довести мелкие реальные дефекты.** Проверь восстановление invalid low/high range draft: сейчас composite range key и раздельные low/high keys могут расходиться. Перепроверь upgrade-таблицу: строка нового оптимизированного варианта не должна выглядеть как расчёт неизменённого старого соглашения. Ошибка сохранения не теряет draft.
7. Подключить export объяснения прогноза Claude 3. Скачать/открыть файл; не называть его заявлением, отправленным в Marketplace.

## Границы

Твоя зона: `src/features/**`, `src/components/**`, не-API `src/app/**`, styles, UI smoke. Не переписывай engine, contracts, persistence и PDF generator. Если нужен hook — описать в handoff и использовать общий контракт. Не рисовать hardcoded успешные результаты вместо отсутствующего engine response.

Сохранить English UI, клавиатуру/focus, guest no-auth и текущие три demo. Не добавлять новый UI framework и не заменять пользовательские финальные материалы.

## Готовность

Пройти весь сценарий из shared brief с реальным движком и storage. Дополнительно: current-year check без next-year income; mobile 360px; invalid draft reload; fixed agreement vs new proposal. Typecheck, затронутые проверки, один build. Снять actual desktop/mobile screens результата, повторного события и фактического SEP; оценить их глазами, не только через DOM assertions.

`docs/handoffs/claude1-round3.md`: реализовано/осталось, dependency SHA, проверенные journeys, пути screenshots. Commit + push `claude1`, не merge main самостоятельно.
