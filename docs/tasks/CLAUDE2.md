# Claude 2 — расчёты, ограничения и варианты

Ветка: **`claude2`**. Прочитай `AGENTS.md`, `docs/TZ.md`, `docs/ENGINE_SPEC.md`, `docs/ARCHITECTURE.md`, общий контракт и reference README. Работай в отдельной копии. Не создавай Python-сервис: перенеси корректную логику в общий TypeScript engine.

## Результат

Два рабочих entry point: текущая проверка ACA-субсидии и двухлетнее сравнение выполнимых действий. Детерминированные расчёты, объяснимые источники, честные блокировки неизвестного/неподдерживаемого. Движок работает без базы, ИИ, регистрации и входа.

## Твои файлы

## Задачи по порядку

1. Прочитать старый Python engine и аудит. Не копировать известные ошибки в TypeScript. Составить точный support guard, включая доходы супругов, покрытие, SEP и неучтённые налоги/кредиты.
2. Создать версионированные rule packs 2026/2027 из официальных источников. Использовать Decimal и формальную политику округления. Зафиксировать статус DRAFT у таблицы инструкции 8962.
3. Реализовать MAGI/SE tax/employee FICA/federal tax/QBI/SEHI/PTC в объявленной области. Индивидуальные wage bases, реальные доходы семьи и пенсионные лимиты обязательны. APTC settlement не вычитается дважды.
4. Решить взаимозависимость SEHI/PTC по допустимым ограничениям, не только fixed point. Обосновать метод поиска на разрывах. Не выдавать локальное уточнение сетки за доказательство глобального результата.
5. Реализовать `assessCurrentRisk`: только текущий год, без обязательного заказа и следующего прогноза. Запас до обрыва относится к дополнительной прибыли и имеет явные предположения.
6. Реализовать `calculateComparison`: отказ/исходный заказ, минимальный и устойчивый в заявленном диапазоне SEP, допустимая разбивка оплаты, пересмотр цены. Соблюдать бюджет и ограничения. Расходы не перемещаются автоматически вслед за доходом.
7. Показать оба года, cash vs retirement и horizon расчёта. Выбирать вариант по заявленной цели. Неподдерживаемый/невыполнимый сценарий не рекомендуется. Если оптимизации нет — корректный обычный ответ.
8. Сформировать полный `YearResult`, structured decisions, trace, source IDs, warnings, fingerprint и версию правил. Никаких формул в LLM и никакого Date.now в финансовой логике.
9. Пройти ограниченные regression groups в ACCEPTANCE и один независимый эталон. Замерить один обычный расчёт/поиск. Исправить реальную ошибку, затем перейти к интеграции — не расширять тесты бесконечно.

## Обязательные ловушки

- Зарплата супруга не уменьшает индивидуальный SS cap владельца бизнеса.
- 175% FPL в 2026 → applicable figure 0.0540.
- 2027 SS wage base $192,300, defined contribution cap $75,000.
- 400% включительно и выше 400% — разные случаи; прибыль ≠ MAGI.
- Положительный APTC не доказывает все условия eligibility below 100%.
- $23k SEHI/PTC контрпример не должен снова исчезнуть из-за ошибочного требования равенства.
- Неизвестный доход супруга не становится нулевым; пропущенный income row не равен подтверждённому отсутствию дохода.
- Неупомянутый налоговый кредит может менять take-home; либо реализовать, либо блокировать затронутую область.
- Нельзя выдавать взнос на пенсионный счёт за экономию продукта или доступные деньги.
