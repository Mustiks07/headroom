Первым небольшим commit + push: `src/domain/deal-planning.ts` со схемами Goal/CashContext/SearchResult/Sensitivity/ActionPackage по общей семантике, engine service signatures, synthetic fixture и `docs/handoffs/round4-contract.md` с SHA. Claude 1/2 должны иметь возможность сразу merge этого коммита и работать независимо.

## Затем закончить backend и пакет действий

1. **Долговечный goal/cash/action state.** Сохранение с revision и идемпотентными событиями, local guest и опциональный Supabase. Старые v1/v2 restore работают; новые поля не исчезают молча. JSON export/restore сохраняет цель, источники, stable IDs фактов и snapshot inclusions. Один повтор import не создаёт второй доход/взнос/напоминание.
2. **Document → reviewed fact.** Подключить существующий intake к конкретному workspace/project/SEP факту. Preview показывает найденные сумму, дату, тип, период и источник; пользователь подтверждает назначение. Не принимать bank transfer за облагаемый доход, неизвестный период — за 2026, один receipt — за годовой итог. Повторный source ID предлагает корректировку/совпадение, не дублирует. Сырые документы не попадают в Git/logs/analytics. Без AI ключа работает CSV/TXT/manual; OCR не имитировать.
3. **Черновик условий клиенту.** Детерминированно собрать из выбранного актуального результата цену, ещё не выполненные платежи/даты, необходимые согласования. Preview/copy/download. Не раскрывать клиенту семейные доходы/субсидию/налоги без явного выбора пользователя. Не отправлять email/сообщения и не считать черновик согласием клиента. Наличие LLM необязательно.
4. **Календарь действий (.ics).** Стабильный UID каждого действия, корректные даты/escaping/timezone, понятный summary. Повторный экспорт того же плана не размножает UID; изменившееся действие обновляет версию. Уже выполненное не предлагается как новое. Точные налоговые/SEP сроки проверять в первичном источнике и учитывать подтверждённое продление; при неизвестном сроке просить дату/показывать условие, не придумывать дедлайн.
5. **Decision package PDF.** Цель, baseline, выбранные условия, деньги по датам с полнотой/предположениями, cash after settlement отдельно, SEP paid/remaining, налоговые последствия, источники и следующие действия. Версии/revision/fingerprint обязательны. Устаревший расчёт нельзя экспортировать как текущую рекомендацию. Это объяснение для обсуждения, не официальная налоговая форма. Сохранить уже работающий annual forecast export.
6. **Подключение UI и transport.** Описать экспортируемые hooks/APIs Claude 1; финансовые поля берутся из результата Claude 2, не пересчитываются в PDF. Mutation stale checks и понятные ошибки; никакого двойного success, когда local сохранён, а cloud отказал.
7. **Готовность к публичному запуску.** Проверить Next/Vercel Node route wiring, limits/runtime, миграции и `.env.example`. Обновить точные шаги deployment. Если действующие env/доступ уже настроены — проверить разрешённый guest путь; если нет, перечислить только реально необходимые имена переменных и непроверенные шаги. Секреты в Git/ответ не выводить. Не публиковать заведомо незавершённую общую сборку вместо релиза Codex.

## Конечная проверка

Один подтверждённый импорт повторно; сохранение/reload/JSON restore нового состояния; отсутствие чужого workspace доступа в действующей cloud модели; stale export; PDF открыть и проверить все страницы; ICS проверить парсером/календарём; client draft сверить с актуальными суммами без лишних семейных данных. Использовать synthetic inputs. Не заменять пользовательские финальные материалы.

Typecheck, релевантные integration checks, один build. `docs/handoffs/claude3-round4.md`: contract SHA, exported hooks, миграции/env, реальные проверки/артефакты и непротестированные внешние сервисы. Commit + push `claude3`. Финальная интеграция main — Codex.
